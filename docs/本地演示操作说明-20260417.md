# 兆方美迪项目管理系统本地演示操作说明

## 一、明天演示的目标

本次演示不需要把所有技术细节讲清楚，重点让客户看到这 4 件事：

1. 系统已经能承接现有台账工作
2. 数据可以围绕“合同”主线拉通
3. 后续单据不需要重复录入大量相同信息
4. 可以形成查询、统计和管理分析视角

建议你把演示重点放在业务价值上，而不是放在 Odoo 这个底层框架上。

## 二、建议使用的演示环境

优先使用你当前本地已经正常的版本演示。

访问地址：

- `http://127.0.0.1:8069`

建议准备两个账号：

- 管理员账号：用于配置和兜底
- `zfmd` 业务账号：用于给客户看业务界面

如果明天来不及进一步收口页面，演示时优先用业务页面、列表和表单，不要过多展示后台管理菜单。

## 三、建议演示顺序

### 1. 先讲业务主线

先告诉客户，这套系统不是单点台账，而是一条业务主线：

- 合同台账
- 开工申请
- 服务记录
- 开票登记
- 回款登记
- 应收计划
- 数据看板/统计

你可以这样解释：

“以前这些信息分散在多张 Excel 里，现在系统以合同为主线，把后续业务环节串起来。”

### 2. 先看合同台账

给客户展示：

- 合同编号
- 客户
- 场站
- 销售经理
- 产品线
- 合同金额
- 已开票
- 已回款
- 未回款

这一步要让客户感受到：

- 合同是主档
- 后续所有业务记录都可以挂在合同下面

### 3. 再看开工、服务、开票、回款、应收

按这个顺序最好：

1. 开工申请
2. 服务记录
3. 开票登记
4. 回款登记
5. 应收计划

重点不是每个字段都讲，而是讲“选了合同之后，信息如何自动带出”。

### 4. 最后看统计/看板

如果本地版当前看板可用，就重点讲：

- 执行中合同
- 超期服务
- 累计开票
- 累计回款
- 到期应收

如果看板不稳定，就用列表页筛选和搜索来替代演示统计能力。

## 四、怎么体现“数据拉通”

这是客户最容易感受到价值的地方。

你可以直接这样演示：

### 场景一：从合同进入后续业务

1. 打开一条合同
2. 展示合同里的客户、场站、产品线、销售经理等信息
3. 进入开工申请或开票登记页面
4. 选择该合同
5. 让客户看系统自动带出相关字段

要强调的点：

- 合同是唯一主线
- 后续业务单据通过关联合同自动带出信息
- 减少重复填写

### 场景二：从合同反查后续执行情况

在合同页面里展示：

- 开工申请数量
- 服务记录数量
- 开票记录数量
- 回款记录数量
- 应收计划数量

要强调的点：

- 不再是“每张表各管各的”
- 管理者可以围绕一份合同看完整执行链路

## 五、怎么体现“减少重复录入”

你可以直接用一句话解释这个设计原则：

“一次录入，多处复用。”

建议你举这几个例子：

### 例子 1：合同录一次，后续共用

合同里录入的这些信息，后面都可以复用：

- 客户
- 场站
- 省区
- 集团
- 产品线
- 销售经理
- 项目内容

### 例子 2：开票和回款不再重复找信息

开票登记、回款登记都直接挂在合同下：

- 不需要每次重新录客户和项目背景
- 统计时也不需要再人工比对多张表

### 例子 3：应收统计自动形成

应收计划和回款记录一旦都挂到合同上：

- 系统就可以自动形成应收余额
- 不再依赖人工在 Excel 里做二次统计

## 六、怎么体现“统计分析”

建议你用“管理问题”去讲，而不是用“技术功能”去讲。

可以让客户看到这些问题现在能回答：

- 当前有多少执行中的合同
- 哪些服务快到期或已经超期
- 哪些合同已经开票但还没回款
- 哪些应收已经到期
- 某个客户/销售经理当前的回款和应收情况

如果看板可用，就从看板讲。

如果看板暂时不用，就从列表筛选讲：

- 按合同状态筛选
- 按销售经理筛选
- 按客户筛选
- 按到期状态筛选

## 七、明天如何说明“导入信息”

如果客户问“Excel 怎么导入”，你建议这样回答最稳：

### 当前阶段建议

系统已经支持承接现有台账结构，历史数据导入建议分阶段进行：

1. 先导入合同台账
2. 再导入开票和回款
3. 最后导入应收计划和服务台账

### 为什么分阶段

因为合同是主线，先有合同主档，后续数据更容易准确关联合同，避免导入后产生孤立记录。

### 明天演示时的说法

“导入不是一次把所有旧表硬塞进去，而是按业务主线逐步迁移，先保证关联准确，再保证统计准确。”

## 八、如果客户问“怎么录数据”

你可以给客户一个很清晰的使用路径：

### 日常录入顺序

1. 先录合同台账
2. 有开工事项时录开工申请
3. 项目执行中录服务记录
4. 商务/财务录开票登记
5. 到账后录回款登记
6. 按合同条款维护应收计划

### 核心使用原则

- 能挂合同的都尽量挂合同
- 能自动带出的就不手填
- 统计结果尽量从系统自动生成，不再靠表外手工维护

## 九、明天不要花太多时间讲的内容

建议少讲这些：

- Odoo 本身是什么
- 服务器怎么部署
- 框架细节
- 权限技术细节

客户更关心的是：

- 能不能覆盖原来的工作
- 能不能少录一点
- 能不能更容易查
- 能不能更容易看应收和回款

## 十、明天建议的结束方式

演示最后建议这样收尾：

“当前版本已经把主业务链路搭起来了，下一步希望请您重点确认三件事：”

1. 字段是否覆盖原台账需求
2. 业务流程顺序是否合理
3. 哪些统计结果最值得优先做强

这样客户更容易给出有效反馈，而不会只说“感觉还可以”。
