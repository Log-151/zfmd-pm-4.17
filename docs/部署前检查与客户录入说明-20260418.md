# 部署前检查与客户录入说明

## 一、部署前最后检查

### 1. 先确认当前版本
- 本地 `git status` 应为干净或只包含本次准备部署的改动
- 关键模块 `zfmd_pm` 可以正常升级
- `admin` 和 `zfmd` 两个账户都能登录

### 2. 本轮重点确认内容
- `zfmd` 登录后只显示业务菜单
- 顶栏已收口，不再暴露无关管理入口
- 浏览器标题、登录页、右上角图标已做品牌化
- `数据看板`、`合同台账`、`开工申请`、`服务记录`、`开票登记`、`回款登记`、`应收计划` 都能打开
- 列表页可新增、查询、导出 Excel

### 3. 建议部署动作
1. 本机提交并推送代码
2. 云服务器 `git pull`
3. 重启 Odoo 容器
4. 执行模块升级
5. 用 `admin` 检查模块升级是否成功
6. 用 `zfmd` 检查业务界面是否正常

## 二、明天给客户演示时建议强调的使用方式

### 导入顺序
建议按下面顺序导入或讲解：

1. `06 销售合同登记台账`
2. `05 销售合同开发票登记台账`
3. `04 销售合同回款登记台账`
4. `09 执行中合同应收款明细台账`

### 为什么这样安排
- `06` 是合同主档，是整套系统的数据主线
- `05` 和 `04` 用来体现“开票、回款挂到合同上”
- `09` 用来体现“应收统计、到期应收、未回款余额”
- `07`、`08` 和 `10` 可以作为第二阶段补充，不建议第一次演示时一次性全上

### 明天可以这样向客户解释
- 先把合同信息录入系统
- 后续开工、服务、开票、回款、应收都围绕合同展开
- 这样可以减少重复录入
- 同一份合同的信息会在后续单据里自动带出
- 系统可以集中做应收、回款和执行情况统计

## 三、客户如果先录入数据，会不会影响开发

### 会有影响，但可以控制
如果客户在当前环境直接开始录入真实数据，后续开发会受到这些影响：

1. 如果我们调整字段结构，可能要做数据迁移
2. 如果我们调整页面和流程，录入习惯可能需要重新适配
3. 如果我们删除或重建测试数据，可能误伤客户已录入的数据

### 建议做法
最好把环境分成两类：

- `演示/开发环境`
  作用：继续改功能、调页面、验证导入逻辑
- `正式录入环境`
  作用：客户开始稳定录入真实数据

### 当前阶段建议
在你和客户需求还没完全定稿前：
- 不建议让客户在唯一环境里大量录入真实正式数据
- 可以少量录入样例或试运行数据
- 每次升级前先备份数据库

## 四、如果客户一定要现在开始录入

可以，但要遵守这 3 条：

1. 每次升级前先做数据库备份
2. 尽量避免大改核心表结构
3. 新功能先在本地或测试环境验证，再上云环境

## 五、当前最稳的策略

- 本地版本：继续作为开发和演示基准版本
- 云上版本：继续对齐本地并逐步完善
- 客户正式开始大规模录数之前，先把主流程和主要字段稳定住
