# 新一轮修改 — 需求拆解与可执行提示词

> 基于用户原始需求，逐条拆解为可执行的标准开发提示词，不遗漏任何一条。
> 日期：2026-06-10

---

## 总体原则

1. **数据优先级**：人工录入 / 导入内容 ＞ 自动计算 / 关联填充。系统仅在无录入内容时才通过关联、计算自动填入。
2. **工作顺序**：合同台账 → 应收计划 → 开票登记 → 回款登记。服务记录、售后服务属于随机信息，不受固定流程约束。
3. **关联主键**：合同台账与项目管理之间，**合同编号 + 场站名称**相同即可视为关联条目。其他模块间的关联需多条件组合判断。
4. **项目管理模块特殊性**：其信息主要依据其他模块的录入信息联动更新，本身是"汇聚视图"而非完全独立的录入模块。

## 二、项目管理 (zfmd.project.management)

### 2.1 到货单 / 验收单 自动判断

**提示词5 — 项目管理到货单/验收单根据应收计划自动计算**
```
在 zfmd.project.management 模型中，arrival_voucher 和 acceptance_voucher
字段改为 computed 字段（或保留存储但通过自动化写入）。

关联规则：
- 通过 合同编号(name) + 场站名称(site_name) 关联 zfmd.receivable.plan
- 遍历所有匹配的 receivable_plan 条目：
  - 只要任一条目的 actual_arrival_date 有值 → arrival_voucher = "有"
  - 全部条目的 actual_arrival_date 都无值 → arrival_voucher = "无"
  - 只要任一条目的 actual_acceptance_date 有值 → acceptance_voucher = "有"
  - 全部条目的 actual_acceptance_date 都无值 → acceptance_voucher = "无"

实现：新增 @api.depends 或定时方法，每当 receivable_plan 的 actual_arrival_date /
actual_acceptance_date 变化时，触发对应 project_management 的更新。
```

### 2.2 合同执行情况 多条件判断

**提示词6 — 项目管理合同执行情况多条件自动判断**
```
在 zfmd.project.management 模型中，contract_execution_status 字段改为 computed。

判断优先级（从上到下匹配，命中即停止，服务状态优先于施工状态）：

条件A：service_end_date 未到（service_end_date >= today 或为空，默认视为未到）
  → "服务中"

条件B：service_end_date 已到（service_end_date < today）
  → "服务结束"

条件C：arrival_voucher = "有" AND acceptance_voucher = "有"
  → "已完工"

条件D：arrival_voucher = "有" AND acceptance_voucher = "无"
  → "施工中"

条件E：arrival_voucher = "无" AND acceptance_voucher = "无"
  → "未开工"

✅ 已确认：服务状态优先。即先判断 service_end_date 是否到期，
再判断施工/完工状态。当同时满足时，服务状态（A/B）排在前面。
```

### 2.3 开票时间 自动关联

**提示词7 — 项目管理开票时间自动从开票登记联动**
```
在 zfmd.project.management 模型中，invoice_date 和 invoice_date_note
改为自动计算字段。

关联规则：
- 通过 合同编号(name) + 客户名称(customer_name) 关联 zfmd.invoice.record
- 若关联到 1 条：invoice_date = 该条 invoice_date，invoice_date_note 留空
- 若关联到 N 条（N>1）：
  - invoice_date = 最新的那条 invoice_date
  - invoice_date_note = 文本拼接所有关联开票条目的时间
    格式如："2025-01-15; 2025-03-20; 2025-06-10"（按时间倒序）
- 若关联到 0 条：invoice_date 留空，invoice_date_note 留空

实现：computed field with @api.depends 或监听 invoice_record 变化自动更新。
```

### 2.4 发票开具情况 联动

**提示词8 — 项目管理发票开具情况与开票登记同步**
```
在 zfmd.project.management 模型中，invoice_status 字段关联最新开票条目的 开票情况。

关联规则：
- 通过 合同编号(name) 关联 zfmd.invoice.record
- 取所有关联开票条目中 create_date 最新（或 invoice_date 最新）的那条
- project_management.invoice_status ← 最新开票条目的 开票情况 字段值

若有关联开票条目，则同步；若无关，则留空。

⚠️ 前提：开票登记模块需先完成"1.1 新增字段：开票情况"（见下文）。
```

### 2.5 财务计算字段

**提示词9 — 项目管理财务计算字段**
```
在 zfmd.project.management 模型中，以下字段改为 computed 或通过自动化方法写入：

1. 总应收款(total_receivable_amount) = 合同总额(contract_amount) - 已回款(paid_amount)
   注意：contract_amount 来自合同总额，已回款来自 payment_record 汇总

2. 实际总应收款(actual_total_receivable_amount) = 合同总额(contract_amount) - 已回款(paid_amount) - 坏账金额(bad_debt_amount)

3. 已开票应收款(invoiced_receivable_amount) = 关联的开票金额总和 - 已回款(paid_amount)
   关联方式：通过 合同编号(name) 关联 zfmd.invoice.record，取 invoice_amount 总和

4. 进度应收款(progress_receivable_amount) = 通过 合同编号(name) 关联的 receivable_plan 中，
   receivable_date ≤ today 的所有 receivable_amount 之和

5. 实际进度应收款(actual_progress_receivable_amount) = 进度应收款 - 已回款(paid_amount) - 坏账金额(bad_debt_amount)

6. 已回款(paid_amount) = 通过 合同编号(name) 关联的 payment_record 中 amount_total 总和

实现方式：
- 使用 @api.depends 或 compute 方法
- 当关联的 payment_record、invoice_record、receivable_plan 数据变更时自动重新计算
- 需注意循环依赖：paid_amount 用于计算其他字段，但本身来自 payment_record
```

### 2.6 合同台账 ↔ 项目管理双向同步

**提示词10 — 合同台账与项目管理双向同步机制**
```
实现 zfmd.contract 与 zfmd.project.management 的双向数据同步。

关联判定：合同编号(name) + 场站名称(site_name/site_id.name) 相同。

触发时机：
- contract.write() 修改核心字段后 → 同步到关联的 project_management
- project_management.write() 修改核心字段后 → 同步到关联的 contract

同步字段清单（两端共有的字段）：
| 合同台账字段        | 项目管理字段              | 同步方向    |
|---------------------|--------------------------|-------------|
| name                | name                     | 双向        |
| partner_id.name     | customer_name            | C→PM (合同推) |
| province_name       | province_name            | 双向        |
| group_name          | group_name               | 双向        |
| site_id.name        | site_name                | 双向        |
| product_line        | product_line             | 双向        |
| project_content     | project_content          | 双向        |
| sale_manager        | contract_sale_manager    | 双向        |
| sale_contact        | sale_contact             | 双向        |
| service_start_date  | service_start_date       | 双向        |
| service_end_date    | service_end_date         | 双向        |
| delivery_department | delivery_department      | 双向        |
| project_manager     | project_manager          | 双向        |
| initial_fee         | initial_fee              | 双向        |
| service_fee         | forecast_service_fee     | 双向        |
| amount_total        | contract_amount          | 双向        |
| contract_project_no | contract_project_no      | 双向        |           ← ⚠️ pm 缺字段
| contract_sign_date  | (新增签约日期字段)        | 双向        |           ← ⚠️ pm 缺字段

⚠️ 防死循环：在 write() 中加入上下文标记（context key），
当触发方标记为 syncing 时，接收方不再次触发反向同步。

⚠️ project_management 缺少字段：
- contract_project_no（项目编号）
- contract_sign_date（签约日期）
需先在 project_management 模型中新增这些字段。
```

```
在 zfmd.invoice.record 模型中，实现与 zfmd.payment.record 的回款联动。

关联规则（三条件同时满足）：
1. 合同编号 相同（display_contract_no）
2. 付款单位 = 开票客户（payment.payer_name = invoice.invoice_partner_name）
3. 客户名称 相同（payment 的 contract.partner_id.name = invoice 的 contract.partner_id.name）

联动逻辑：

  - actual_payment_date_note = 所有回款日期文本拼接
    格式："2025-01-15; 2025-03-20; 2025-06-10"

```

### 4.3 不含税金额自动计算 + 校验

**提示词16 — 开票登记不含税金额自动计算与校验**
```
在 zfmd.invoice.record 模型中实现：

1. 自动计算不含税金额：
   - 当 amount_untaxed 字段为空（无人工输入）时：
     不含税金额 = invoice_amount / (1 + tax_rate_float)
   - 税率来源：tax_rate 字段（Char类型，需解析为浮点数）
   - 默认税率：若 tax_rate 为空或无法解析，默认使用 0.13
   - 若 invoice_amount 也为空，不计算

2. 税额计算（建议新增税额字段）：
   - tax_amount (Float, compute) = invoice_amount - amount_untaxed
   - 或 tax_amount = amount_untaxed × tax_rate_float

3. 三者关系校验：
   含税金额(invoice_amount) = 不含税金额(amount_untaxed) + 税额(tax_amount)
   当关系不满足时（差额 > 0.01），在视图层标红提示：
   - 使用 widget 的 decoration-danger 或
   - 新增一个 warning 字段标记
   - 或通过 CSS class 标红不一致的行

⚠️ 重要说明：
- tax_rate 当前为 Char 类型，需在计算时做 float 解析 ← ✅ 已确认，录入的税率信息转为数值计算
- 建议新增 tax_amount 计算字段，避免校验逻辑复杂化
- 若用户手动修改了 amount_untaxed，则以手动值为准，仅做校验不覆盖
```

### 4.4 开票登记更新后联动应收计划和项目管理

## 七、跨模块联动总表

### 7.1 联动关系矩阵

```
┌──────────────────┬────────────┬──────────────────────────┬──────────────────────────────────────────┐
│ 触发模块         │ 目标模块   │ 关联条件                 │ 同步字段                                │
├──────────────────┼────────────┼──────────────────────────┼──────────────────────────────────────────┤
```

### 7.2 联动触发机制设计

**提示词21 — 统一联动触发框架**
```
建议在 tools/ 下新建 sync_engine.py，集中管理跨模块联动逻辑。

核心方法：
- sync_contract_to_pm(contract) — 合同 → 项目管理
- sync_pm_to_contract(pm_record) — 项目管理 → 合同
- sync_payment_to_invoice(payment) — 回款 → 开票
- sync_payment_to_receivable(payment) — 回款 → 应收
- sync_invoice_to_pm(invoice) — 开票 → 项目管理
- sync_receivable_to_pm(receivable) — 应收 → 项目管理
- sync_contract_to_service(contract) — 合同 → 服务记录

触发方式：
- 在各模型的 write() / create() 方法中，通过 with_context 或直接调用 sync_engine
- 使用 context key {'skip_sync': True} 防止递归死循环

性能考虑：
- 单条修改只触发关联条目的重新计算（不要全表扫描）
- 批量导入场景下使用 delayed sync（导入完成后再批量同步）
```
