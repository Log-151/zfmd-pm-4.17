# 扩展架构接口设计

本文档用于约束后续供应链、工程施工等子系统的扩展方式。当前一期系统以稳定使用和保护已录入数据为优先，不对既有模型做大规模拆分。

## 模块边界

- `zfmd_pm` 保持为当前项目管理应用模块，承载已有合同、开工、服务、开票、回款、应收、项目管理、售后服务等台账。
- 后续新增子系统优先创建独立模块，例如 `zfmd_supply_chain`、`zfmd_construction`。
- 公共能力逐步抽取到基础模块。短期内公共接口先保留在 `zfmd_pm` 中，待新子系统稳定后再迁移到 `zfmd_base`。
- 不直接移动已有模型的技术名称、菜单 xmlid、权限 xmlid，避免影响已部署数据库。

## 公共业务字段

新增模型优先继承 `zfmd.business.mixin`，统一以下字段：

- `province_name`
- `group_name`
- `site_name`
- `product_line`
- `project_content`
- `sale_manager`
- `sale_contact`
- `note`

该 mixin 同时提供 `_prepare_business_vals_from_contract(contract)`，用于从合同主档同步公共业务信息。

已有模型暂不强制迁移到该 mixin。若后续迁移，应按模型逐个处理，并完成导入、导出、列表、表单和看板验证。

## 合同关联接口

新增合同子台账优先继承 `zfmd.contract.link.mixin`，统一以下字段和行为：

- `contract_id`
- `source_contract_no`
- `display_contract_no`
- `contract_match_state`
- `_prepare_contract_link_vals(contract)`
- `_prepare_contract_snapshot_vals(contract)`

合同主表通过 `zfmd.contract._related_record_models()` 声明现有子台账配置。新增子台账如需挂到合同主表，应扩展该配置，而不是在多个按钮和统计方法中散落硬编码。

## 导入导出

导入继续复用现有 `wizards/import_utils.py` 的字段映射、预览、结果统计能力。

导出列定义短期仍使用 Python 方法，但公共列组应复用 `export_mixin.py` 中的辅助函数：

- `_contract_link_columns()`
- `_business_context_columns()`
- `_sales_contact_columns()`

新增模块不应复制整套导出样板。若后续模块数量继续增加，再升级为 XML 或数据模型驱动的导出列配置。

## 演进原则

- 先新增接口，再迁移旧模型。
- 先服务新模块，再逐步减少旧代码重复。
- 不以架构调整为由改变历史数据口径。
- 涉及字段迁移、模块拆分、xmlid 迁移时，必须提供升级脚本和回滚方案。
