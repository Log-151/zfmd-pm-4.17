# 生产上线检查清单

## 部署目标

- 新云服务器临时地址：`http://47.94.85.246/`
- 该地址仅用于部署阶段连通性验证；正式对用户开放前必须绑定域名并启用 HTTPS。

## 当前结论

生产配置与本地开发配置已经分离。生产环境使用 `docker-compose.prod.yml`，具备以下基线：

- PostgreSQL 不发布宿主机端口，Odoo 只绑定 `127.0.0.1`。
- 通过 Nginx 提供 HTTPS，数据库管理路由在代理层阻断。
- `list_db=False`，并使用固定数据库名和 `dbfilter`。
- PostgreSQL 应用角色没有超级用户、建库、建角色和复制权限。
- 数据库口令与 Odoo 主密码使用 Docker secrets，不写入仓库和 Compose 环境变量。
- Odoo 与 PostgreSQL 镜像使用不可变摘要，服务有健康检查、自动重启与日志轮转。
- Odoo 生产配置启用多进程、内存/时间限制，且不安装演示数据。

## 首次部署

1. 安装 Docker、Compose、Nginx 和证书工具，防火墙只开放 SSH、HTTP、HTTPS。
2. 创建三个不同的强随机密码，文件末尾不要包含多余空行：

   ```bash
   install -d -m 700 secrets
   openssl rand -base64 48 > secrets/postgres_admin_password
   openssl rand -base64 48 > secrets/odoo_db_password
   openssl rand -base64 48 > secrets/odoo_admin_password
   chmod 600 secrets/*
   ```

3. 将 `deploy/nginx/zfmd.conf.example` 复制到 Nginx 配置目录，替换域名和证书路径；校验后重载：

   ```bash
   sudo nginx -t
   sudo systemctl reload nginx
   ```

4. 构建并启动：

   ```bash
   docker compose -f docker-compose.prod.yml build --pull
   docker compose -f docker-compose.prod.yml up -d
   docker compose -f docker-compose.prod.yml ps
   ```

5. 首次初始化或恢复数据库后安装/升级模块：

   ```bash
   docker compose -f docker-compose.prod.yml stop odoo
   docker compose -f docker-compose.prod.yml run --rm --no-deps odoo \
     -d zfmd-PM -u zfmd_pm \
     --stop-after-init --no-http
   docker compose -f docker-compose.prod.yml up -d odoo
   ```

## 已有数据库迁移警告

`docker-compose.prod.yml` 使用新的命名卷。不要在承载现有数据的服务器上直接执行 `up -d` 并误以为旧数据会自动出现。

迁移必须在维护窗口完成：

1. 停止业务写入并在备份中心生成“系统恢复包”。
2. 下载 ZIP 到另一台设备，执行 `unzip -t`。
3. 在隔离环境恢复 ZIP，核对登录、附件、合同数量、金额抽样和 Excel 导出。
4. 为旧环境保留数据库目录和 Odoo filestore 的只读快照。
5. 在新生产卷恢复数据库与 filestore，再升级模块。
6. 使用数据库管理员确认应用角色已降权：

   ```bash
   docker compose -f docker-compose.prod.yml exec -T db \
     psql -U postgres -d postgres \
     -c "ALTER ROLE odoo NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION;"
   ```

7. 完成验收后才切换域名；旧环境至少保留一个回退周期。

## 账号与权限

- 删除或停用演示、访客、共享账号；每人使用独立账号。
- 上线前重置 `admin`、`zfmd` 及所有管理员密码，禁止使用历史默认口令。
- 日常业务用户只分配 `ZFMD Viewer` 或所需业务角色。
- 只有备份负责人分配 `ZFMD Backup Manager`；只有系统维护人员分配 Odoo“设置”权限。
- 管理员开启双因素认证；离职账号立即停用。
- Odoo 数据库主密码仅用于服务器维护，不提供给日常用户。

## 上线验收

- HTTPS 强制跳转，证书链正常，浏览器无混合内容。
- 公网访问 `/web/database/manager` 返回 404；公网无法连接 5432、8069、8072。
- 登录、退出、权限切换正常；访客无法导入、备份、重算预警或调用同步。
- 合同、开工、服务、开票、回款、应收和项目管理分别完成新增、查询、导出抽样。
- 手动生成并下载系统 ZIP 与 Excel 快照；定时备份成功执行一次。
- 从系统 ZIP 在隔离环境完成一次恢复，附件可打开。
- 备份至少保留一份异机/对象存储副本；仅保存在同一云服务器不算有效灾备。
- 配置外部存活监控、磁盘空间告警、备份失败告警和 HTTPS 到期告警。

## 每次发布

1. 冻结写入并生成上线前系统备份。
2. 在测试库执行模块升级和全部自动化测试。
3. 构建新镜像，不复用浮动标签。
4. 在生产库执行模块升级，重启并检查健康状态与错误日志。
5. 完成核心业务冒烟测试和备份下载测试。
6. 记录镜像摘要、模块版本、执行人、时间和回退点。

## 回退

代码回退必须与数据库/filestore 回退成套进行。若升级包含模型或数据迁移，不能只换回旧镜像。停止服务后恢复上线前 ZIP 或数据库快照及对应 filestore，再启动上一版本镜像。
