## 一、项目管理 (zfmd.project.management)

### 1.1 修改进度应收款计算方式

**提示词1 — 项目管理进度应收款计算逻辑修正**
```
在 zfmd.project.management 模型中，修改 progress_receivable_amount 的计算逻辑。

当前逻辑：progress_receivable_amount 通过合同编号关联的 receivable_plan 中
receivable_date ≤ today 的所有 receivable_amount 之和。

新逻辑：进度应收款 = (通过合同编号关联的应收计划条目中，应收时间 ≤ 今天的
所有应收金额之和) - 已回款(paid_amount)

即：
progress_receivable_amount = SUM(receivable_plan.receivable_amount 
  WHERE receivable_plan.display_contract_no = project_management.name
  AND receivable_plan.receivable_date <= today) - paid_amount

若计算结果为负数，取 0。

实现方式：
- 在 sync_engine.py 的 refresh_projects 方法中加入此计算逻辑
- 或新增 @api.depends 的 compute 方法
- 当 receivable_plan 的 receivable_amount / receivable_date 变更时触发重算
- 当 payment_record 的 amount_total 变更时触发重算（影响 paid_amount）
```

### 1.2 修改坏账金额计算方式

**提示词2 — 项目管理坏账金额从应收计划联动计算**
```
在 zfmd.project.management 模型中，修改 bad_debt_amount 的计算逻辑。

新逻辑：坏账金额 = 通过合同编号关联的应收计划条目中，所有标记为坏账的
应收金额之和。

关联规则：
- 通过 合同编号(name/contract_id) 关联 zfmd.receivable.plan
- 筛选 receivable_plan 中 exception_type = "bad_debt" 的条目
- bad_debt_amount = SUM(这些条目的 receivable_amount)

若 receivable_plan 尚未新增坏账金额字段（见提示词8），则暂时使用
receivable_amount 作为该笔坏账条目的坏账金额。

实现方式：
- 在 sync_engine.py 的 refresh_projects 方法中加入此计算逻辑
- 当 receivable_plan 的 exception_type / receivable_amount 变更时触发重算
```

### 1.3 修复客户编码筛选问题

**提示词3 — 修复项目管理客户编码筛选失效**
```
问题描述：
1. 客户编码为 103、157 等数字编码的条目无法通过筛选器筛出
2. 筛选客户编码 201 时只出现一个条目，但实际该客户有多条项目条目
3. 数据库中已有合同编码的客户，在系统中没有自动填全客户编码

分析与修复：

  project_management 记录的 customer_code
  UPDATE zfmd_project_management pm
  SET customer_code = rp.customer_code
  FROM zfmd_contract c
  JOIN res_partner rp ON c.partner_id = rp.id

实现步骤：
1. 在 project_management 的 _prepare_contract_link_vals 或 write/create 中
   增加 customer_code 的自动填充（从 contract.partner_id.customer_code）
2. 在 sync_engine.refresh_projects 中增加 customer_code 同步
3. 编写 migration 脚本修复历史数据
4. 在 dashboard.py 的 project_management config 中，
   确认 customer_code 在 keyword_fields 中可被正确搜索
```

### 4.2 应收余额自动计算逻辑修正

**提示词9 — 开票登记应收余额计算逻辑修正**
```
在 zfmd.invoice.record 模型中，修改 receivable_balance 的计算逻辑。

当前逻辑：
receivable_balance = max(invoice_amount - actual_payment_amount, 0)

新逻辑：
应收余额 = 合同金额(contract_amount) - 实际回款金额(actual_payment_amount)
即：receivable_balance = max(contract_amount - actual_payment_amount, 0)

修改 _compute_receivable_balance 方法：
@api.depends("contract_amount", "actual_payment_amount")
def _compute_receivable_balance(self):
    for record in self:
        balance = (record.contract_amount or 0.0) - (record.actual_payment_amount or 0.0)
        record.receivable_balance = balance if balance > 0 else 0.0

⚠️ 依赖字段从 ("invoice_amount", "actual_payment_amount") 
改为 ("contract_amount", "actual_payment_amount")
```

### 4.3 状态自动联动逻辑

**提示词10 — 开票登记状态与应收余额联动**
```
在 zfmd.invoice.record 模型中，修改状态(state)的自动判断逻辑。

规则：
1. 系统默认每个开票登记条目的状态是"未回款"(open)
2. 当应收余额(receivable_balance) = 0 时，自动将状态变为"已回款"(paid)
3. "已作废"(cancel) 状态需手动更改，不由系统自动设置

修改 action_recompute_state_from_payment 方法：

def action_recompute_state_from_payment(self):
    for record in self:
        # "已作废"状态需要手动更改，不由系统自动设置
        if record.state == "cancel":
            continue
        # 手动锁定状态时跳过自动计算
        if record.state_manual_override and not self.env.context.get("force_state_auto"):
            continue
        # 应收余额为0 → 已回款
        if (record.receivable_balance or 0.0) <= 0:
            record.state = "paid"
        # 有开票日期且未回款 → 未回款
        elif record.invoice_date or record.invoice_amount:
            record.state = "open"
        else:
            record.state = "draft"
    return True

⚠️ 注意：
- 新建时默认状态为 "open"（未回款），而非 "draft"
- 创建时的 default 值改为 "open"
- 只有手动将状态改为"已作废"时才会变为 cancel
```

### 7.4 开工申请预计合同额统计口径调整

**提示词20 — 经营管理周例会统计表开工申请预计合同额统计口径调整**
```
在 dashboard.py 的 _management_values 方法中，调整开工申请(start)的统计逻辑。

需求：
1. 只计算 2026 年累计（从 2026-01-01 到查询截至日期）
2. 统计值 = 截止到查询截至日期，历年所有开工申请中：
   - 排除已经有合同号的（contract_match_state = "matched"）
   - 排除已取消的（cancel_date IS NOT NULL 或 state = "cancel"）
   - 取这些条目的"预计应收款(estimated_receivable)"之和
3. 不再是按时间区间截取的开工申请

修改 _management_values 方法：

在计算 start 值时：
- 如果统计年份为 2026 年，使用全局累计而非区间累计
- 统计 domain：
  [
      ("entry_state", "=", "confirmed"),
      ("contract_match_state", "!=", "matched"),  # 排除有合同号的
      ("cancel_date", "=", False),                 # 排除已取消的
  ]
- 不加时间范围限制（取所有历年累计）
- 金额字段从 estimated_contract_amount 改为 estimated_receivable

具体代码修改：
def _management_values(self, date_from, date_to, include_snapshot=False):
    contracts = self._sales_report_contracts(date_from, date_to)
    
    # 开工申请：2026年累计，使用预计应收款，排除有合同号和已取消
    start_domain = [
        ("entry_state", "=", "confirmed"),
        ("contract_match_state", "!=", "matched"),
        ("cancel_date", "=", False),
    ]
    if self.sale_manager:
        start_domain.append(("sale_manager", "ilike", self.sale_manager))
    start_amount = sum(
        self.env["zfmd.project.start"].search(start_domain).mapped("estimated_receivable")
    )
    
    return {
        "contract": sum(contracts.mapped("amount_total")),
        "start": start_amount,
        ...
    }
```
