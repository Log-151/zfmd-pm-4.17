# 正式备份操作清单

## 目标
- 让当前项目进展可以被完整恢复。
- 保证业务导出可核对，系统冷备份可恢复。

## 适用范围
- 本地开发环境
- 以后云上环境可沿用同一原则，但执行命令另行整理

## 备份前提
- 先确认当前功能点已验证完毕
- 先导出 6 个业务台账 Excel
- 再执行完整冷备份

## 固定执行顺序
1. 登录系统，分别导出：
   - 合同台账
   - 开工申请
   - 服务记录
   - 开票登记
   - 回款登记
   - 应收计划
2. 在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup_local.ps1
```

3. 打开 `backups\时间戳` 目录，确认存在：
   - `addons`
   - `docs`
   - `postgres_data`
   - `odoo_data`
   - `docker-compose.yml`
   - `odoo.conf`
   - `BACKUP_README.txt`
4. 抽查：
   - 1 份业务导出 Excel 能否打开
   - `BACKUP_README.txt` 能否打开
5. 记录本次备份时间、目的和说明

## 脚本默认行为
- 会先执行 `docker compose down`
- 再复制数据库目录、文件目录、代码目录和文档目录
- 最后自动执行 `docker compose up -d`

## 备份文件命名
- 目录名默认：`yyyyMMdd-HHmmss`
- 建议在备份目录外层再按用途区分，例如：
  - `发布前备份`
  - `客户演示前备份`
  - `结构调整前备份`

## 恢复原则
1. 停止本地 Odoo
2. 恢复 `postgres_data`
3. 恢复 `odoo\data`
4. 恢复 `addons` 和配置文件
5. 启动 `docker compose up -d`

## 说明
- 业务导出不能替代数据库冷备份
- 数据完整性以数据库和文件目录为准
- 任何升级、批量导入、结构调整前，必须先做一次完整备份
