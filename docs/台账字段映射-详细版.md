# 台账字段映射-详细版

这份文档的目标，是把客户当前 04-10 台账中的字段，逐步映射到 Odoo 模型中。

映射原则：

- 同一类主数据只保留一个主入口
- 后续单据优先从合同或场站自动带出
- 能计算的不手工录入
- 能通过规则判断的不新增重复字段

---

## 1. 04 回款台账 -> `zfmd.payment.record`

原表核心字段：

- 回款日期
- 付款单位
- 省（区）
- 集团
- 场站名称
- 产品线
- 合同项目内容
- 合同号
- 汇票回款(元)
- 现金回款(元)
- 回款比例
- 款项名称
- 签订合同销售经理
- 销售联系人
- 备注
- 类型
- 合同金额

系统映射：

- `回款日期` -> `payment_date`
- `付款单位` -> `payer_name`
- `省（区）` -> `province_name`
- `集团` -> `group_name`
- `场站名称` -> `site_name`
- `产品线` -> `product_line`
- `合同项目内容` -> `project_content`
- `合同号` -> `contract_id`
- `汇票回款(元)` -> `bill_amount`
- `现金回款(元)` -> `cash_amount`
- `回款比例` -> `payment_ratio_text`
- `款项名称` -> `payment_item_name`
- `签订合同销售经理` -> `sale_manager`
- `销售联系人` -> `sale_contact`
- `备注` -> `note`

建议处理：

- `合同金额` 不建议在回款记录重复保存，优先从合同自动读取
- `类型` 建议后续视业务再决定是否新增 `payment_type`
- `回款总额` 由系统自动计算：`汇票 + 现金`

- `税率` -> `tax_rate`
- `不含税金额` -> `amount_untaxed`
- `承诺回款日期` -> `promised_payment_date`

- `实际回款日期` -> `actual_payment_date`
- `实际回款金额` -> `actual_payment_amount`
- `发票快递单号` -> `express_no`
- `作废时间` -> `cancel_date`
- `作废原因` -> `cancel_reason`

- 未回款页 -> `state = open`
- 已回款页 -> `state = paid`

后续自动规则：

- 若 `承诺回款日期` 已过且 `实际回款金额为空或不足`，触发预警
- 开票记录与回款记录联动后，自动算 `未回款金额`

- `场站类别` -> 场站对象 `site_category`

- `正式预报时间` -> `formal_forecast_date`

- `预计签订服务合同时间` -> `expected_contract_sign_date`
- `续签服务合同情况说明` -> `renewal_note`

“其他信息”页建议映射：

- `续签前服务到期时间` -> 可作为历史字段，建议二期扩展
- `续签后服务开始时间` -> 可用于更新下一条服务记录开始时间
- `中断时间（月）` -> `break_months`
- `备注` -> `renewal_note` 追加说明

后续自动规则：

- 到期前 90/60/30 天提醒
- 已超期自动进入异常列表
- 超期月数由系统自动计算，不建议长期手填

## 7. 10 项目管理统计表 -> 主要来自系统汇总，不建议手工录入

10 表本质不是一张原始录入表，而是若干业务数据汇总后的结果。

### 7.1 “执行中合同”页

主要来源：

- 合同：`zfmd.contract`
- 开票：`zfmd.invoice.record`
- 回款：`zfmd.payment.record`
- 应收：`zfmd.receivable.plan`
- 开工：`zfmd.project.start`
- 服务：`zfmd.service.record`

建议系统自动生成的字段：

- 合同执行情况
- 到货单/验收单情况
- 已回款
- 总应收款
- 实际总应收款
- 已开票应收款
- 进度应收款
- 实际进度应收款
- 开票时间
- 是否有坏账
- 坏账金额
- 已开票坏账金额

### 7.2 “已开工初装项目”页

主要来源：

- 开工申请
- 合同

建议系统自动生成或半自动维护：

- 项目年份
- 执行情况
- 应收款
- 应付款

### 7.3 “无服务合同项目”页

主要来源：

- 服务记录
- 合同关联状态

系统规则：

- 服务记录存在
- 但当前没有有效服务合同关联
- 自动进入“无服务合同项目”

### 7.4 “售后服务”页

主要来源：

- 合同
- 售后服务单
- 服务记录

说明：

- 10 表应尽量做成系统看板和导出报表
- 不建议继续维护一张单独的录入表

## 8. 一期哪些字段建议先不做

为保证尽快上线，一期建议延后这些字段：

- 合同存档原件/复印件
- 合同存档份数
- 一级/二级/三级公司复杂层级
- 保函开具情况
- 第三方接口费
- 不算销售收入
- 不算销售业绩
- 客户编码的完整治理

原因：

- 它们对核心业务链路影响较小
- 可以等主流程稳定后再补

---

## 9. 一期数据导入顺序

建议导入顺序：

1. 客户
2. 场站
3. 合同
4. 开工申请
5. 服务记录
6. 开票记录
7. 回款记录
8. 应收计划

原因：

- 后续数据都要依赖合同、客户、场站主键
- 先建主档，再建流水，错误率最低

---

## 10. 需要系统自动生成的能力

这些内容建议做成规则，不继续人工维护：

- 回款总额
- 发票未回款金额
- 服务到期预警
- 超期月数
- 合同执行状态
- 无合同开工项目识别
- 无服务合同项目识别
- 执行中合同应收汇总
- 坏账/扣款汇总
