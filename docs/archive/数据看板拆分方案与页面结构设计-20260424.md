# 数据看板拆分方案与页面结构设计（一期）

日期：2026-04-24

## 一、结论

本期建议把“数据看板”正式拆成两个二级页面：

1. 全局概览
2. 统一查询中心

这是可行且值得现在推进的结构调整。

原因：
- “全局概览”适合放关键指标、预警、待办提醒，不承担复杂查询交互。
- “统一查询中心”适合承担条件筛选、结果预览、导出、跳明细，不再和概览混在一个页面里。
- 两类页面职责分开后，后续再接入大模型自然语言查询也更清晰：AI 应该接在“统一查询中心”，而不是概览页。

同时，客户新增的“所有金额单位统一为元”属于全系统口径改造，必须落实，但不建议零散修改。应作为单独专项统一推进。

## 二、页面结构建议

### 1. 全局概览

定位：
- 项目管理首页
- 面向“今天先看什么”的快速判断

页面内容建议：
- 顶部指标卡
  - 合同总额（元）
  - 开票总额（元）
  - 回款总额（元）
  - 应收总额（元）
  - 未回款总额（元）
- 预警区
  - 已逾期服务场站
  - 未来 3 个月到期服务场站
  - 已开票未回款项目
  - 未关联合同的开工/服务记录
  - 当月应收未进入回款期记录
- 快速入口
  - 查看回款明细
  - 查看开票明细
  - 查看应收明细
  - 查看服务到期明细
- 用户自定义预警
  - 先做成固定规则 + 开关配置
  - 暂不做复杂拖拽式看板定制

### 2. 统一查询中心

定位：
- 所有跨台账查询、筛选、统计、导出统一入口

页面结构建议：
- 统一条件区
  - 查询对象
  - 时间范围
  - 关键词
  - 合同编号
  - 客户/付款单位
  - 场站
  - 销售经理
  - 省区
  - 集团
  - 产品线
  - 状态
- 结果摘要区
  - 查询对象
  - 匹配记录数
  - 金额口径
  - 汇总金额（元）
  - 时间范围说明
  - 当前筛选摘要
- 结果预览区
  - 表格预览
  - 可横向滚动
  - 表头保持清晰，不做竖排压缩
- 操作区
  - 应用查询
  - 查看结果明细
  - 导出当前结果
  - 重置条件

## 三、交互原则

### 全局概览
- 只负责“看态势、看预警、点进去”
- 不承担复杂筛选和表格分析
- 每个卡片和预警都能跳到统一查询中心或对应台账

### 统一查询中心
- 先筛选，再看结果，再导出，再跳明细
- 当前筛选结果必须可导出
- 结果预览必须和跳转明细、导出保持同一套口径
- 后续 AI 查询能力也应先生成筛选条件，再由系统执行

## 四、金额单位改为“元”的评估

这个改动必须做，但属于全系统专项，不建议作为当前数据看板拆分的一部分顺手改。

影响范围包括：
- 合同台账
- 开票登记
- 回款登记
- 应收计划
- 开工申请中的金额字段
- 服务记录中的金额字段
- 所有导入器
- 所有导出器
- 数据看板汇总口径
- 预警阈值和统计口径
- 文档和操作说明

### 建议处理方式
- 单独立项为“金额单位统一改造”
- 所有金额字段显示统一为“元”
- 导入口径统一按“元”
- 导出表头统一按“元”
- 数据看板汇总统一按“元”
- 回归时重点核对：导入值、页面显示值、导出值、统计值是否一致

## 五、排序需求评估

“合同信息条目按时间为基准自动排序”可行，但必须先明确排序规则。

建议规则：
1. 优先按合同签订日期升序/降序（需确定默认方向）
2. 同日期时按导入顺序
3. 无签订日期时按导入顺序
4. 最后兜底按合同编号

说明：
- 不建议模糊写成“按时间自动排序”而不定义时间字段
- 建议先在合同台账中固定默认排序规则，再决定是否允许用户切换排序方式

## 六、实施顺序建议

### 第一阶段（当前）
- 数据看板拆成：全局概览 + 统一查询中心
- 先完成页面结构和菜单结构
- 不在这一阶段接大模型 API

### 第二阶段
- 统一查询中心增强
  - 条件联动
  - 结果摘要优化
  - 结果预览优化
  - 明细跳转优化

### 第三阶段
- 金额单位统一改造（元）
- 作为专项改造处理，不与别的功能混做

### 第四阶段
- AI 自然语言查询接入统一查询中心
- 由 AI 负责理解问题，系统负责执行结构化查询

## 七、当前建议

当前立刻进入的工作项应为：
1. 数据看板菜单拆分
2. 全局概览页面骨架
3. 统一查询中心页面骨架重构

金额单位统一改为“元”已经确定要做，但建议排在数据看板拆分完成后，单独作为专项改造落地。
