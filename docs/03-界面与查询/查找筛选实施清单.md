# 查找、筛选与分析下一阶段实施清单

## 当前判断
当前系统已经具备基础录入、导入、导出和业务备份能力，下一阶段重点应转到：
- 查找是否全面
- 筛选是否灵活
- 分析是否贴近业务

## 当前缺口
### 1. 查找字段还不够全
- 目前各模块搜索栏和筛选项只覆盖了一部分字段
- 与 04-10 样例表相比，还没做到“所有重要表头都可筛选”

### 2. 自定义筛选能力不够清晰
- 虽然 Odoo 自带筛选，但业务用户不容易理解内部字段
- 需要把字段命名、筛选入口和分组规则收成业务语言

### 3. 分析入口还不够明确
- 当前分析主要依赖列表分组和少量看板
- 还缺少按客户、场站、销售经理、合同状态、回款状态的一键分析入口

## 下一阶段建议顺序
### 第一批：查找/筛选底座
- 合同台账补齐更多业务字段搜索
- 开工申请补齐更多业务字段搜索
- 服务记录补齐更多业务字段搜索
- 开票登记补齐更多业务字段搜索
- 回款登记补齐更多业务字段搜索
- 应收计划补齐更多业务字段搜索

### 第二批：业务预设筛选
- 执行中合同
- 未关联合同的开工申请
- 已超期服务
- 已开票未回款
- 已回款
- 未到期应收
- 已到期应收
- 部分回款应收

### 第三批：分组与基础分析
- 按销售经理分组
- 按省区分组
- 按集团分组
- 按产品线分组
- 按客户分组
- 按场站分组

### 第四批：个性化分析入口
- 合同执行情况分析
- 开票与回款差异分析
- 应收账龄和超期分析
- 按客户维度项目情况分析

## 开发原则
- 所有筛选项优先使用业务表头名称
- 能按正式表头理解的，不暴露内部字段名
- 金额统一按万元展示
- 分析能力建立在数据完整和备份完整基础上，不允许为追求图表效果牺牲数据准确性
