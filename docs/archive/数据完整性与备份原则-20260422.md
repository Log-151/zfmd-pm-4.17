## 数据完整性与备份原则

### 一、定位

这不是普通优化项，而是系统正式投入使用前的硬性验收标准。

后续所有台账模块都必须满足：

1. 导入时，原表中的有效信息不能被静默丢失。
2. 导入后，系统中必须能完整查看这些信息。
3. 备份导出时，导出的表格表头必须完整，且数据内容必须可回溯到导入原表。
4. 日期、人名、金额、合同号、说明性文本等字段，不允许因为系统解析失败而直接变成空值或 0。

### 二、总原则

#### 1. 原文优先保留

凡是 Excel 中存在但不一定能稳定结构化的数据，都必须保留原文。

典型场景：

- `/`
- `未开始`
- `未流转`
- `预测服务2年`
- `建模扩容`
- `部分质保款`

处理原则：

- 系统尝试解析出规范化字段时，可以写入结构化字段。
- 同时必须保留原文字段，避免信息被覆盖或丢失。

#### 2. 金额统一以“万元”为业务单位

后续所有涉及金额的业务字段，统一按“万元”作为系统展示与业务输入输出单位。

包括但不限于：

- 合同总额
- 开票金额
- 实际回款
- 应收金额
- 销售经理承诺回款金额
- 汇票回款
- 现金回款

验收要求：

- 导入前 Excel 的金额单位如果不是“万元”，必须在导入规则中明确换算。
- 导入后系统界面与导出表头都必须明确标注“（万元）”。
- 不允许出现因为单位未统一而造成数值错位。

#### 3. 备份导出必须可回表

“备份”不是简单导出几列核心字段，而是要满足实际办公恢复需要。

要求：

- 导出表头应尽量覆盖对应业务台账的完整表头。
- 导出后的内容应能被用户理解并用于核对。
- 后续正式导出模板要尽量靠近原始 Excel 台账格式。

### 三、导入验收标准

每个导入器都必须通过以下检查：

#### A. 字段完整性

- 表中所有关键字段都能导入
- 暂不能结构化的字段必须进入原文字段
- 不允许无提示地丢字段

#### B. 值准确性

- 日期与原表一致
- 人名与原表一致
- 合同号与原表一致
- 金额与原表一致
- 说明文本与原表一致

#### C. 行数准确性

- 真实业务记录数必须与导入成功数一致
- `合计 / 总计 / 汇总 / 小计 / 空白说明行` 必须被明确过滤
- 过滤逻辑必须可说明、可复验

#### D. 重复导入可控

- 同一份样例重复导入时，不应无控制膨胀
- 新增、更新、跳过规则必须清晰

### 四、导出/备份验收标准

后续每个模块都要补齐“完整导出”能力，验收时至少检查：

1. 表头是否齐全
2. 金额单位是否统一为“万元”
3. 导出的字段是否和系统当前页面一致
4. 原文字段是否可导出
5. 导出后的 Excel 是否能用于人工核对

### 五、当前阶段的实施顺序

先不急着做最终导出模板美化，按下面顺序推进：

1. 导入正确
2. 页面正确显示
3. 列选择中字段完整
4. 完整导出可用
5. 最后再做贴近原台账样式的导出模板

### 六、当前结论

从现在开始，项目中的“完成导入”不再只表示“数据进库了”，而必须同时满足：

- 值没错
- 字段没丢
- 原文保留
- 单位统一
- 能完整导出备份

这条规则对：

- 06 合同台账
- 05 开票登记
- 04 回款登记
- 09 应收计划
- 07 开工申请
- 08 气象服务记录

全部生效。
