## 数据完整性与备份原则

### 一、定位

这不是普通优化项，而是系统正式投入使用前的硬性验收标准。

后续所有台账模块都必须满足：

1. 导入时，原表中的有效信息不能被静默丢失。
2. 导入后，系统中必须能完整查看这些信息。
3. 备份导出时，导出的表格表头必须完整，且数据内容必须可回溯到导入原表。
4. 日期、人名、金额、合同号、说明性文本等字段，不允许因为系统解析失败而直接变成空值或 0。

### 二、总原则

#### 1. 原文优先保留

凡是 Excel 中存在但不一定能稳定结构化的数据，都必须保留原文。

典型场景：

- `/`
- `未开始`
- `未流转`
- `预测服务2年`
- `建模扩容`
- `部分质保款`

处理原则：

- 系统尝试解析出规范化字段时，可以写入结构化字段。
- 同时必须保留原文字段，避免信息被覆盖或丢失。

#### 2. 金额统一以“元”为业务单位

后续所有涉及金额的业务字段，统一按“元”作为系统展示与业务输入输出单位。

包括但不限于：

- 合同总额
- 开票金额
- 实际回款
- 应收金额
- 销售经理承诺回款金额
- 汇票回款
- 现金回款

验收要求：

- 导入前 Excel 的金额单位如果不是“元”，必须在导入规则中明确换算。
- 导入后系统界面与导出表头都必须明确标注“（元）”。
- 不允许出现因为单位未统一而造成数值错位。

#### 3. 备份导出必须可回表

“备份”不是简单导出几列核心字段，而是要满足实际办公恢复需要。

要求：

- 导出表头应尽量覆盖对应业务台账的完整表头。
- 导出后的内容应能被用户理解并用于核对。
- 后续正式导出模板要尽量靠近原始 Excel 台账格式。

### 三、导入验收标准

每个导入器都必须通过以下检查：

#### A. 字段完整性

- 表中所有关键字段都能导入
- 暂不能结构化的字段必须进入原文字段
- 不允许无提示地丢字段

#### B. 值准确性

- 日期与原表一致
- 人名与原表一致
- 合同号与原表一致
- 金额与原表一致
- 说明文本与原表一致

#### C. 行数准确性

- 真实业务记录数必须与导入成功数一致
- `合计 / 总计 / 汇总 / 小计 / 空白说明行` 必须被明确过滤
- 过滤逻辑必须可说明、可复验

#### D. 重复导入可控

- 同一份样例重复导入时，不应无控制膨胀
- 新增、更新、跳过规则必须清晰

### 四、导出/备份验收标准

后续每个模块都要补齐“完整导出”能力，验收时至少检查：

1. 表头是否齐全
2. 金额单位是否统一为“元”
3. 导出的字段是否和系统当前页面一致
4. 原文字段是否可导出
5. 导出后的 Excel 是否能用于人工核对

### 五、当前阶段的实施顺序

先不急着做最终导出模板美化，按下面顺序推进：

1. 导入正确
2. 页面正确显示
3. 列选择中字段完整
4. 完整导出可用
5. 最后再做贴近原台账样式的导出模板

### 六、当前结论

从现在开始，项目中的“完成导入”不再只表示“数据进库了”，而必须同时满足：

- 值没错
- 字段没丢
- 原文保留
- 单位统一
- 能完整导出备份

这条规则对：

- 06 合同台账
- 05 开票登记
- 04 回款登记
- 09 应收计划
- 07 开工申请
- 08 气象服务记录

全部生效。
# 正式备份方案

## 目标
- 保证系统每天新增录入数据都能完整导出、完整备份、完整恢复。
- 保证导出的台账表头尽量与样例 Excel 一致，金额统一按“元”。
- 保证备份不仅能防止数据丢失，还能支持人工核对和恢复。

## 一、业务层导出
每天或每次集中录入后，按业务台账导出一次 Excel。

### 导出范围
- 合同台账
- 开工申请
- 服务记录
- 开票登记
- 回款登记
- 应收计划

### 导出要求
- 导出表头使用正式中文。
- 金额字段统一使用“（元）”。
- 业务表头尽量覆盖样例 Excel 的全部有效表头。
- 业务导出默认不展示“原文”“原始导入数据”“内部关联字段”。
- 07/08 的原文和原始导入数据继续保留在系统中，用于系统级备份和回表核对，不直接暴露在日常业务导出里。
- 导出的每一行都必须对应系统中的一条真实记录，不允许静默丢行。

### 建议频率
- 日常录入阶段：每天导出一次。
- 批量导入后：导入完成立即导出一次。
- 大规模修改前：先导出一次作为业务层快照。

## 二、系统层完整备份
业务层导出不能替代系统层完整备份。系统层必须同时备份：
- PostgreSQL 数据库
- Odoo 文件目录

当前本地 Docker 路径：
- 数据库目录：`~/temp/zfmd-pm-4.17\postgres_data`
- Odoo 文件目录：`~/temp/zfmd-pm-4.17\odoo\data`

### 1. 数据库备份
在项目根目录执行：

```powershell
docker exec zfmd_pg pg_dump -U odoo -d zfmd_pm -F c -f /tmp/zfmd_pm.backup
docker cp zfmd_pg:/tmp/zfmd_pm.backup ./backups/zfmd_pm_YYYYMMDD_HHMM.backup
```

说明：
- `-F c` 生成 PostgreSQL 自定义格式备份，便于恢复。
- 备份文件名必须包含日期和时间。

### 2. 文件目录备份
将以下目录整体压缩备份：

```text
~/temp/zfmd-pm-4.17\odoo\data
```

建议命名：

```text
zfmd_filestore_YYYYMMDD_HHMM.zip
```

### 3. 组合备份
一次正式备份应至少包含：
- `zfmd_pm_YYYYMMDD_HHMM.backup`
- `zfmd_filestore_YYYYMMDD_HHMM.zip`
- 当天业务导出的 6 个台账 Excel

## 三、恢复原则
恢复必须同时恢复：
- 数据库
- 文件目录

只恢复数据库、不恢复文件目录，可能导致附件或系统文件不完整。

### 数据库恢复示例
```powershell
docker cp ./backups/zfmd_pm_YYYYMMDD_HHMM.backup zfmd_pg:/tmp/zfmd_pm.backup
docker exec zfmd_pg dropdb -U odoo zfmd_pm
docker exec zfmd_pg createdb -U odoo zfmd_pm
docker exec zfmd_pg pg_restore -U odoo -d zfmd_pm /tmp/zfmd_pm.backup
```

### 文件目录恢复示例
- 停止 Odoo 容器
- 清理或替换 `odoo\data`
- 解压对应时间点的 `zfmd_filestore_YYYYMMDD_HHMM.zip`
- 再启动 Odoo

## 四、备份后的核对清单
每次正式备份后至少检查：
- 6 个业务台账 Excel 是否都能打开
- 表头是否完整
- 金额列单位是否都是“元”
- 当天新增记录是否在导出表里可见
- 数据库备份文件是否成功生成
- 文件目录压缩包是否成功生成

## 五、执行节奏建议
### 每天
- 导出当天相关台账

### 每周
- 做一次完整数据库备份 + 文件目录备份

### 每次模块升级前
- 必做完整备份

### 每次批量导入前
- 至少做业务层导出

## 六、上线后的红线
- 任何一次导入都不能默默丢字段、丢行、改单位。
- 任何一次备份都必须能回到样例表核对口径。
- 任何一次结构调整前，必须先完成完整备份。
